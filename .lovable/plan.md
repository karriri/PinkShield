# Этап 1 из мастер-плана: аудит + AI Brain

Остальные части (база знаний RAG, OCR, библиотека, подписки, ML Lab и др.) пойдут следующими этапами, каждый со своим планом. Всё, что уже работает, остаётся без изменений.

## 1. Аудит (отчёт в чате)
- Проверка всех страниц, данных, прав доступа, автоматических напоминаний, ИИ-вызовов и медицинских ограничений.
- Запуск проверки безопасности и всех автотестов.
- Итог по статусам: «Работает и проверено», «Работает, нужна настройка», «Подготовлена структура», «Не сделано».
- Список найденных слабостей и дублирования.

## 2. AI Brain — единый центр для всех запросов к ИИ
- Все ИИ-функции идут через один центр: он определяет тип задачи, выбирает модуль, проверяет ответ, ограничивает время ожидания и при сбое показывает безопасный запасной ответ (исходный текст или «не удалось объяснить»), а не выдуманный.
- Единые медицинские правила для всех модулей: без диагнозов, лечения, процентов риска, «вы здоровы».
- Технический журнал для администратора: модуль, длительность, успех/ошибка, примерный расход. Медицинские тексты в журнал не попадают.
- Лимит запросов на пользователя, чтобы не тратить кредиты впустую.

## 3. Модули
Сразу рабочие (переносим существующие в общий центр):
1. Помощник по заключениям — как сейчас.
2. Навигатор — как сейчас.

Новые рабочие:
3. Объяснение медицинского термина — короткое пояснение, только образовательное.
4. Подготовка к приёму — список вопросов врачу по типу визита (из календаря), без советов о лечении.
5. Проверка безопасности в сообществе — при публикации поста ИИ отмечает возможно опасные медицинские советы; пост не блокируется, а попадает модераторам с пометкой.

Подготовлены, но не включены (ждут базу знаний, этап 2):
6. Ответы по базе знаний.
7. Образовательные материалы.
Они честно помечены как «скоро», без имитации.

## 4. Где пользователь это увидит
- Термины: кнопка «Объяснить» в базе знаний и в результатах заключения.
- Подготовка к приёму: кнопка в карточке приёма в календаре.
- Модерация: новая метка «ИИ: возможный опасный совет» и вкладка «Журнал ИИ» для администратора.

## 5. Хранение заключений (решение принято)
Хранить только с явного согласия пользователя, с возможностью удалить — это реализуется в этапе «Личная библиотека», не сейчас. Сейчас по-прежнему ничего не сохраняется.

## 6. Тесты
- Каждый модуль: формат ответа, отказ на запрос диагноза/лечения, запасной ответ при сбое и тайм-ауте.
- Журнал не содержит медицинского текста; обычный пользователь журнал не видит.
- Лимит запросов срабатывает.
- Все прежние тесты проходят.

## Технические детали
- `src/lib/ai/orchestrator.server.ts`: типизированный реестр модулей (system prompt, JSON Schema, валидатор выхода, fallback), тайм-аут, обработка GatewayError; вызовы через `@lovable.dev/ai-gateway`, текущая модель сохраняется.
- `src/lib/ai/modules/*.ts`; общие ограничения в `src/lib/ai/safety.ts` (на основе report-safety/guidance-check).
- `src/lib/ai.functions.ts`: серверные функции с requireSupabaseAuth; report/navigator переводятся на оркестратор без смены поведения.
- Миграция: `ai_request_log` (module, duration_ms, outcome, tokens, user_id; без текстов), запись только через SECURITY DEFINER функцию, чтение — has_role admin; `ai_rate_limits` с атомарным счётчиком; колонка `posts.ai_flag` + авто-отчёт в content_reports.
- ML Lab — только структура в последующем этапе.
